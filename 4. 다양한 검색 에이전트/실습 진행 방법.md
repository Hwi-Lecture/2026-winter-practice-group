# RAG 실습 진행 방법

실습은 다섯 가지입니다. 각 실습은 따로 진행할 수 있습니다.

| 순서 | 실습 | 폴더 | 실행 |
| --- | --- | --- | --- |
| 1 | 텍스트 추출 | `1. 텍스트 추출/1. 코드기반과LLM기반` | 터미널 |
| 2 | 폴더·파일명 검색 | `2. 검색 가능한 문서/1. 폴더 기반 검색` | `메일 챗봇 열기.pyw` |
| 3 | 목차 기반 검색 | `2. 검색 가능한 문서/2. 목차 기반 검색` | `설명서 챗봇 열기.pyw` |
| 4 | 표·DB 기반 검색 | `2. 검색 가능한 문서/3. 표·DB 기반 검색` | `표 챗봇 열기.pyw` |
| 5 | 통합 검색 에이전트 | `2. 검색 가능한 문서/4. 통합 검색 에이전트` | `통합 에이전트 열기.pyw` |

## 사전 준비

- Python 3 (모든 실습)
- `python-docx` 패키지 (실습 1): `pip install python-docx`
- `pandas`, `openpyxl` 패키지 (실습 4): `pip install pandas openpyxl`
- Claude API 키 (실습 2~5)
  - `2. 검색 가능한 문서/.env.example`을 복사해 `.env`로 만들고 키를 입력합니다.
  - `.env`에는 `anthropic_api_key=` 또는 `ANTHROPIC_API_KEY=` 어느 쪽으로 적어도 됩니다.
  - 환경 변수 `ANTHROPIC_API_KEY`로 설정해도 됩니다.

## 실습 2~5 공통 화면

- `.pyw` 파일을 더블클릭하면 브라우저에 실습 화면이 열립니다. 마치면 화면의 **앱 종료**를 누릅니다.
- 화면 위쪽에서 기능을 켜고 끌 수 있고, 켠 기능에 따라 **추가된 기능 / 살펴볼 점** 안내가 바뀝니다.
- 답변 아래 **Claude에게 보낸 내용 보기**를 누르면 질문 하나에 Claude를 몇 번 호출했는지, 매번 무엇을 보내고(system, tools, messages) 무엇을 받았는지 볼 수 있습니다.

## 실습 1. 텍스트 추출

폴더: `1. 텍스트 추출/1. 코드기반과LLM기반`

| 파일 | 설명 |
| --- | --- |
| `키키테크_사내규정_행동강령.docx` | 원본 워드 문서 |
| `extract_docx.py` | 코드 기반 추출 스크립트 |
| `키키테크_사내규정_행동강령.txt` | 코드로 추출한 결과 |
| `키키테크_사내규정_행동강령.md` | Vision Language Model로 추출한 결과 |

### 진행 순서

1. `키키테크_사내규정_행동강령.docx`를 열어 문서의 구성(제목, 표, 목록 등)을 함께 살펴봅니다.
2. 코드 기반 추출을 실행합니다.
   ```
   cd "1. 텍스트 추출/1. 코드기반과LLM기반"
   python extract_docx.py
   ```
   `키키테크_사내규정_행동강령.txt`가 생성(덮어쓰기)됩니다.
3. `.txt` 결과를 원본과 비교해 문제점을 찾습니다. (제목·목록·표의 구조가 어떻게 표현되는지)
4. `.md` 결과를 열어 같은 내용이 어떻게 추출되었는지 확인하고, 마크다운 문법(제목, 목록, 표)을 설명합니다.

## 실습 2. 폴더·파일명 검색

폴더: `2. 검색 가능한 문서/1. 폴더 기반 검색`

날짜 폴더(`2026-11-16` ~ `2026-11-22`)에 메일 53통(`.txt`)이 들어 있습니다. 챗봇은 질문과 겹치는 단어가 많은 메일을 최대 3통 고르고, 고른 메일을 읽어 답합니다. 답변의 `[1]` 같은 번호가 근거 메일입니다.

### 검색 기능

| 기능 | 내용 |
| --- | --- |
| ① 폴더명·파일명 검색 (항상 켜짐) | 날짜 폴더명과 파일명(메일 제목)에서 질문의 단어를 찾습니다. |
| ② 본문까지 검색 | 메일 본문에 질문의 단어가 있는지도 봅니다. |
| ③ 검색어 바꿔 다시 검색 | 읽은 메일로 답을 못 찾으면 Claude가 검색 도구에 새 검색어를 넣어 다시 검색합니다. (최대 2번) |

②와 ③은 따로 켤 수 있습니다. ①만 켠 상태에서 ③을 켜면 Claude가 바꾼 검색어도 파일명에서만 찾습니다.

### 예시 질문

| 구분 | 질문 |
| --- | --- |
| 제목에 단서가 있는 질문 | 초등학생도 보호자가 함께 가면 워크숍에 참여할 수 있나요? / 워크숍 당일 주차 문의입니다. 지하 주차장은 어떻게 무료로 이용할 수 있나요? / 인쇄 견적은 얼마이고 최종 PDF 제출 기한은 언제인가요? |
| 본문에만 단서가 있는 질문 | 엘리베이터에서 내리면 오른쪽과 왼쪽 중 어느 쪽 복도로 가야 하나요? / 차량 번호를 등록하면 몇 시간 무료인가요? / 수업용 예제 문서 세 개의 주제는 각각 무엇인가요? |
| 단어가 다르거나 여러 메일에 흔한 질문 | 승강기에서 내리면 어느 쪽 복도로 가야 하나요? / 워크숍 장소는 어디인가요? / 대여용 노트북은 몇 대 준비되어 있나요? |

### 확인할 점

- ①만 켰을 때
  - 제목에 단서가 있는 질문과 본문에만 단서가 있는 질문의 결과를 비교합니다.
  - 같은 질문 앞에 "주차 문의입니다."만 붙였을 때 검색 목록과 답변이 어떻게 달라지는지 봅니다.
  - '시간'처럼 흔한 단어가 들어간 파일명이 잡히면 엉뚱한 메일이 후보가 됩니다.
- ②를 켰을 때
  - 본문에만 단서가 있는 질문이 해결되는지 봅니다.
  - '노트북'은 16통, '장소'는 9통에서 나옵니다. 걸리는 메일은 많은데 읽는 메일은 3통뿐입니다.
  - 워크숍 장소는 처음에 '배움실 A'였다가 '3층 모임실 B'로 바뀌었습니다. 바뀌기 전 메일이 검색되면 답이 어떻게 되는지 봅니다.
  - '승강기'처럼 메일에 쓰인 단어와 다른 단어로 물으면 찾지 못합니다.
- ③을 켰을 때
  - **Claude에게 보낸 내용 보기**에서 도구 사용 요청 → 도구 실행 결과가 오가는 모습을 봅니다.
  - Claude가 어떤 검색어로 바꿨는지, '승강기' 질문이 해결되는지 봅니다.
  - 다시 검색해도 해결되지 않는 질문을 찾아봅니다.
- 생각해 볼 점
  - 단어가 아니라 뜻으로 메일을 찾으려면 무엇이 필요할지
  - 여러 메일에 같은 내용이 있을 때 최신 정보를 고르려면 어떻게 해야 할지

## 실습 3. 목차 기반 검색

폴더: `2. 검색 가능한 문서/2. 목차 기반 검색`

귀뚜라미 카본매트 온돌 KME 사용설명서를 대상으로 합니다. 챗봇은 먼저 페이지별 제목·요약 목록(`카본매트_KME_페이지별_검색목록.md`)으로 관련 페이지를 최대 5개 고르고, 그 페이지 본문만으로 답한 뒤 근거 원문을 함께 보여 줍니다.

### 실행

1. `설명서 챗봇 열기.pyw`를 더블클릭합니다.
2. 예시 질문이나 오른쪽의 테스트 질문 8문항을 보내거나 직접 질문을 입력합니다.
3. 마치면 화면의 **앱 종료**를 누릅니다.

터미널로 실행할 때는 `python chatbot.py "질문 내용"`입니다.

### 확인할 점

- 어떤 질문에 잘 대답하고, 어떤 질문에 잘 대답 못하는지?
  - 한 페이지에서 답이 나오는 질문(E2 오류 코드)과 여러 페이지를 함께 봐야 하는 질문(취침·수면기능 비교, 세탁과 건조, 리모컨 연결)을 비교합니다.
  - 설명서에 없는 질문(리모컨 배터리 규격)과 설명서와 무관한 질문(김치볶음밥)에 어떻게 답하는지 봅니다.
  - 선택된 페이지가 테스트 문서의 근거 페이지와 일치하는지, 답변 아래 근거 원문이 실제 설명서 내용인지 확인합니다.
  - **Claude에게 보낸 내용 보기**에서 1번째 호출(페이지 고르기)에는 목록만, 2번째 호출(답하기)에는 고른 페이지 본문만 보내는 모습을 봅니다.
- 현재 방식의 한계점은 무엇인지?
  - 페이지는 목차의 제목·요약만 보고 고르므로, 요약에 드러나지 않은 내용은 고르지 못할 수 있습니다.
  - 답변 하나를 만들 때 Claude를 두 번 호출하고, 읽는 페이지는 최대 5쪽입니다.
  - 목차와 요약 목록이 있어야 쓸 수 있습니다. 목차가 없는 문서나 여러 문서에는 어떻게 적용할지 생각해 봅니다.
- 한계점을 극복하기 위해선 어떤 방법을 시도해 볼 수 있을지?
  - 페이지 요약을 더 자세히 쓰거나 키워드를 추가하기
  - 선택된 페이지에 답이 없으면 다른 페이지를 다시 고르기
  - 목차 검색과 본문 검색을 함께 쓰기

## 실습 4. 표·DB 기반 검색

폴더: `2. 검색 가능한 문서/3. 표·DB 기반 검색`

워크숍 신청자 표(34명)를 조회합니다. 화면에 실행한 조회, 조회 결과, 답변이 함께 표시됩니다.

### 조회 기능

| 기능 | 내용 |
| --- | --- |
| ① 고정 조회 | 앱에 준비된 조회(인원 세기, 명단 보기)를 Claude가 고르고 조건값만 채웁니다. 이름 공백, 날짜 형식은 앱 코드가 미리 정리합니다. |
| ② 자유 쿼리 | Claude가 컬럼 구조만 보고 pandas 코드 또는 SQL을 직접 작성합니다. |
| ③ 값 예시 함께 보내기 | (자유 쿼리) 컬럼별 실제 값 예시를 표 구조와 함께 보냅니다. |
| ④ 결과가 비면 다시 조회 | (자유 쿼리) 결과가 비었거나 오류가 나면 이전 쿼리와 결과를 알려 주고 다시 쓰게 합니다. (최대 2번) |

①, ②는 둘 중 하나를 고르고, ③, ④는 ②를 고른 상태에서 켜고 끌 수 있습니다.

### 확인할 점

- ① 고정 조회
  - 어려운 질문(취소 인원, 11월 19일, 김서연 님)이 맞게 나오는지, 그 이유는 무엇인지 봅니다.
  - '거동이 불편한 분' 질문에서 비고 단어를 무엇으로 넣는지, 평균 나이처럼 준비된 조회가 없는 질문을 어떻게 처리하는지 봅니다.
- ② 자유 쿼리
  - 쉬운 질문에서 pandas와 SQL의 쿼리를 나란히 비교합니다.
  - ①에서 맞았던 어려운 질문이 틀리는지 보고, 답변보다 실행한 쿼리와 조회 결과를 먼저 봅니다.
  - 조건이 맞지 않아 결과가 비어도 오류 없이 "없다"는 답이 나올 수 있습니다.
- ③ 값 예시
  - '취소/취소요청', '2026-11-19/2026.11.19'가 값 예시에 보일 때 쿼리가 달라지는지 봅니다.
  - 이름은 34개라 예시에 모두 들어가지 않습니다. 김서연 님 질문은 어떻게 되는지 봅니다.
- ④ 다시 조회
  - 김서연 님 질문에서 두 번째 쿼리가 어떻게 바뀌는지 봅니다.
  - 결과가 비지는 않았지만 틀린 경우(11월 19일에 3명만 나옴)는 다시 조회하지 않습니다.
- 생각해 볼 점
  - 고정 조회와 자유 쿼리 중 어느 쪽이 정확하고, 어느 쪽이 더 많은 질문에 답할 수 있는지
  - 표에 없는 정보(워크숍 장소와 시간)는 어떤 검색 방식으로 찾아야 하는지

## 실습 5. 통합 검색 에이전트

폴더: `2. 검색 가능한 문서/4. 통합 검색 에이전트`

메일, 설명서, 신청자 표를 검색하는 도구를 Claude에게 주고, 어떤 도구를 쓸지와 몇 번 쓸지는 Claude가 정합니다. 앱은 Claude가 요청한 도구를 실행해 결과를 돌려주기만 합니다. 자료는 `데이터` 폴더에 들어 있어 이 폴더만 있으면 실행됩니다.

| 자료 | 도구 |
| --- | --- |
| 메일 53통 | `search_mails`: 제목·본문 단어 검색, 최대 3통 |
| 카본매트 설명서 | `list_manual_pages`: 페이지별 제목·요약 목록 / `read_manual_pages`: 고른 페이지 본문 |
| 신청자 표 | `count_applicants`: 인원 세기 / `list_applicants`: 명단 보기 (실습 4의 고정 조회와 같은 방식) |

### 확인할 점

- 질문마다 어떤 자료의 도구를 골랐는지, 화면의 **에이전트가 사용한 도구** 목록으로 확인합니다.
- 두 자료를 함께 봐야 하는 질문에서 도구를 이어서 쓰는지, 자료끼리 내용이 다를 때 알려 주는지 봅니다.
- **Claude에게 보낸 내용 보기**에서 호출할 때마다 이전 도구 결과가 쌓여 함께 보내지는 모습을 봅니다.
- 화면 위쪽에서 자료 하나를 끄고 같은 질문을 했을 때 다른 자료로 답하려 하는지, 확인할 수 없다고 하는지 봅니다.
